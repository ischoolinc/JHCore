# 匯入基本資料調整 0807

## 問題

學生基本資料匯入精靈在產生／處理「資料修正頁」時，可能出現：

```text
並未將物件參考設定為物件的執行個體。
Object reference not set to an instance of an object.
```

此問題與近期 Excel／UI 欄位由「父親／母親」改為「家長1／家長2」後，驗證與資料修正頁的欄位對應不完全一致有關。

---

## 1. 根因

主要有兩類風險會在「資料修正頁」流程觸發未預期例外：

### A. 欄位名稱對應不一致（NullReference / 對應失敗）

驗證規則、`ValidateColumn.Name`、`SheetReader` 欄位字典使用內部名稱（`父親*`／`母親*`），Excel 原始標題為 `家長1*`／`家長2*`。

若在 `CorrectSheetOutput.Output()` 以錯誤名稱呼叫：

- `_reader.GetCell(each.Name)`
- `_columns[each.Column].Index`

當對應找不到時，舊程式碼可能直接對 `null` 取用成員，或僅顯示泛用 NullReference，無法辨識是哪個欄位失敗。

### B. 「資料修正頁」工作表清理邏輯過寬

建構子將「尋找工作表」與「ClearContents／CreateRange／SetStyle」包在同一個 `try/catch`。

空工作表的 `MaxDataRow`／`MaxDataColumn` 可能為 `-1`，清理時丟出例外後會被誤判為「工作表不存在」，進而再建立同名工作表，造成重複名稱或後續異常。

### C. ValidateColumn 綁定舊 SheetColumn

`CreateValidateColumns()` 原本在 `RefreshImportSource()` 之前執行，`ValidateColumn` 可能綁到舊的 `SheetColumn`（`SourceName`／實體儲存格已失效），不利資料修正頁顯示與連結。

---

## 2. 造成問題的欄位

與家長別名轉換相關：

| Excel／UI | 內部（XML／驗證） |
| --- | --- |
| 家長1姓名 | 父親姓名 |
| 家長2姓名 | 母親姓名 |
| 家長1*（其他既有欄） | 父親* |
| 家長2*（其他既有欄） | 母親* |

驗證規則（`JH_S_FieldValidationRule.xml`）仍使用 `父親姓名`／`母親姓名`，未改動。

---

## 3. `_reader.GetCell()` / `_columns[]` 是否可能為 null

| 呼叫點 | 舊行為風險 | 修正後 |
| --- | --- | --- |
| `_reader.GetCell(each.Name)` | 欄位名稱對不上時可能 KeyNotFound／後續 NRE | `ResolveColumn`／明確例外；`GetCell` 結果再做 null 檢查 |
| `_columns[each.Column]` | 訊息欄位與驗證欄集合不一致時失敗 | `TryResolveColumn`（含家長別名對應）；家長欄失敗拋明確訊息 |

---

## 4. 修正後家長1／家長2 對應規則

維持既有設計，不改 XML／資料庫結構：

```text
Excel／UI：家長1*  ↔  內部：父親*
Excel／UI：家長2*  ↔  內部：母親*
```

實作位置：

- `SheetReader.NormalizeParentImportFieldName`：Excel → 內部
- `SheetReader.DenormalizeParentImportFieldName`：內部 → Excel／UI
- `SheetReader.TryResolveColumn`／`ResolveColumn`：查詢時同時支援兩種名稱
- `ValidateColumnCollection.TryResolveColumn`：驗證訊息欄位解析
- 既有 `TryValidateParentSourceNames`：Excel 僅有舊「父親／母親」標題時不可勾選匯入

## 7. Null 防護變更

1. `CorrectSheetOutput.Output`：`GetCell` 後若為 null，拋出含 DisplayName／內部名稱的例外。
2. 驗證訊息欄位：`TryResolveColumn`；家長相關對應失敗拋明確例外，其他未在驗證欄集合的訊息略過（避免識別欄重複檢查等干擾）。
3. `SheetReader.ResolveColumn`：找不到欄位時拋出含對應說明的 `ArgumentException`。
4. 建構子參數 null 檢查。

---

## 8. 「資料修正頁」工作表處理變更

1. **查找**與**清理／格式化**分離；找不到才新建，不清空失敗時不再誤建同名工作表。
2. `MaxDataRow`／`MaxDataColumn` &lt; 0 時略過 `ClearContents`。
3. `CreateRange` 使用的列／欄下限保護為 0。
4. 標題列改寫 `DisplayName`（Excel `家長1／家長2` 原始標題）。
5. 無錯誤時仍依原邏輯 `OutputComplete` 移除工作表。

## 9. 測試案例與結果

| Case | 情境 | 結果 |
| --- | --- | --- |
| 1 | Excel 含 `家長1姓名`／`家長2姓名` | 程式碼層：正規化＋驗證欄建立＋資料修正頁輸出路徑可對應；建置通過 |
| 2 | Excel 僅 `父親姓名`／`母親姓名` | 既有 `TryValidateParentSourceNames` 停用勾選；不會僅因內部名變成可匯入 |
| 3 | `家長1姓名` 驗證錯誤 | 錯誤註解對應 `父親姓名` 驗證欄；修正頁標題顯示 `家長1姓名`；來源儲存格公式連結修正頁 |
| 4 | `家長2姓名` 驗證錯誤 | 同 Case 3，對應 `母親姓名` |
| 5 | 家長1＋家長2 皆錯 | 兩欄皆可解析；不應再出現泛用 NRE |
| 6 | 無驗證錯誤 | `OutputComplete` 移除資料修正頁（行為不變） |
| 7 | 已存在資料修正頁／空頁 | 重用並安全清理；不因空表誤建重複名稱 |

> 端對端需在可連線環境以匯入精靈實機確認；本次已完成程式碼路徑檢查與 **MSBuild Debug 建置成功**。
