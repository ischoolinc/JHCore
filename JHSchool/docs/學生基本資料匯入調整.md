# 學生基本資料匯入調整

## 1. 問題描述

學生基本資料匯入已將 Excel／UI 家長欄位改為 `家長1`／`家長2`，並在內部正規化為既有 `父親`／`母親`。

當 Excel 同時包含新舊欄位時，例如：

- `家長1姓名`
- `父親姓名`

舊版 `NormalizeParentImportFieldNames()` 會把兩者都正規化成內部名稱 `父親姓名`，因而拋出：

```text
重覆的欄位名稱：父親姓名
```

`家長2`／`母親` 亦有相同問題。

## 2. 根因

正規化採單次掃描，未區分：

- 新 Excel 標題（`家長1`／`家長2`）
- 舊 Excel 標題（`父親`／`母親`）

因此同一內部欄位出現兩次時直接視為重複錯誤，無法依「新欄位優先」略過對應舊欄。

## 3. 修改檔案

| 檔案 | 說明 |

未修改：

## 4. 修改方法

### `SheetReader.NormalizeParentImportFieldNames()`

改為兩段式：

1. **Pass 1**  
   掃描原始 Excel 欄位；凡標題以 `家長1`／`家長2` 開頭者，計算對應內部名稱並加入 preferred 集合。

2. **Pass 2**  
   - `家長1`／`家長2`：正規化為 `父親`／`母親` 後加入結果集合（保留 `SourceName`）。  
   - 舊 `父親`／`母親`：若 preferred 已有「同一內部欄位名稱」，略過該舊欄；否則保留。  
   - 其他欄位：行為不變。  
   - 真正重複（例如兩個 `家長1姓名`）仍拋出 `重覆的欄位名稱`。

### 新增 helper

- `IsPreferredParentSourceName(string sourceName)`
- `IsLegacyParentSourceName(string sourceName)`

## 5. 家長1／家長2 優先規則

| 情境 | 行為 |
| --- | --- |
| 僅有 `家長1xxx` | 正規化為內部 `父親xxx`，可匯入 |
| 僅有 `父親xxx` | 保留內部欄位；UI 仍因 `SourceName` 不是 `家長1xxx` 而不可勾選 |
| 同時有 `家長1xxx` + `父親xxx` | 採用 `家長1xxx`；略過對應舊 `父親xxx`；不拋重複錯誤 |
| 同時有 `家長2xxx` + `母親xxx` | 採用 `家長2xxx`；略過對應舊 `母親xxx`；不拋重複錯誤 |
| `家長1姓名` + `父親電話` | 不同內部欄位，各自獨立處理；不因存在任一 `家長1` 就刪除全部 `父親` |

優先比對單位為「完整內部欄位名稱」，不是整組家長前綴。

正規化後仍維持：

```text
SourceName = Excel 實際標題（如 家長1姓名）
Name       = 內部匯入名稱（如 父親姓名）
AbsoluteIndex 指向 Excel 實體欄位
```

因此 `reader.GetValue("父親姓名")` 讀到的是 `家長1姓名` 實體欄值。

## 6. 為何 XML／資料庫仍使用父親／母親

本次只調整 Excel 欄位正規化優先順序，不改儲存結構。既有資料流維持：

```text
Excel 家長1xxx
→ SheetColumn.SourceName = 家長1xxx
→ SheetColumn.Name = 父親xxx
→ BulkColumn 父親xxx
→ GenerateInsertRequest / GenerateUpdateRequest
→ XML 父親結構
→ 資料庫
```

```text
Excel 家長2xxx
→ SheetColumn.SourceName = 家長2xxx
→ SheetColumn.Name = 母親xxx
→ BulkColumn 母親xxx
→ GenerateInsertRequest / GenerateUpdateRequest
→ XML 母親結構
→ 資料庫
```

不新增 XML 節點 `家長1`／`家長2`。

# 第二部分：群組欄位選擇完整性檢查（0809）

## 12. 問題描述

欄位選擇頁以往用 `ImportItem.IsGroupColumn`（Excel 實際出現的子欄位數是否 > 1）決定是否呼叫 `CheckAccept()`。

因此當 Excel 只含群組的一部分欄位時，例如：

- 僅有 `監護人:電話`（缺 `監護人:學歷`／`監護人:職業`）
- 僅有 `前級:學校名稱`（缺 `前級:學校所在地` 等）

`IsGroupColumn == false`，完整性檢查被略過，欄位仍可勾選。  
實際匯入時 `BulkDescription.GenerateUpdateRequest()` 以 `acceptColumns.ContainGroup(...)` 執行整個 `ElementGenerator`，對缺失子欄呼叫 `reader.GetValue(...)`，才出現：

```text
來源資料中不包含此欄位
```

使用者必須走到最後匯入步驟才發現問題。

## 13. 根因

- **錯誤依據**：以 Excel 側欄位數（`SheetColumns.Count > 1`）判定是否為群組。
- **正確依據**：應以系統 `BulkDescription`（`Context.BulkDescription.Columns` 依 `BulkColumn.GroupName` 分組）判定多欄位群組。
- `BulkColumnCollection.GetColumnList()` 僅做欄位交集，不是本問題根因；本次未修改該方法。
- 未硬編碼「監護人」「前級」等群組名稱。

為何 Excel 側 `IsGroupColumn` 不足：

| Excel 內容 | `IsGroupColumn` | BulkDescription 群組 | 舊行為 |
| --- | --- | --- | --- |
| 僅 `監護人:電話` | false | `監護人其它資訊`（3 欄） | 略過 `CheckAccept`，可勾選 |
| 完整監護人三欄 | true | 同上 | 有呼叫 `CheckAccept` |
| 僅 `前級:學校名稱` | false | `前級畢業資訊`（5 欄） | 略過 `CheckAccept`，可勾選 |

## 15. 修改方法

### `DisplayColumns()`

以既有 `GroupBulkColumn(bfields)` 結果為準：

```text
isBulkGroup =
  bfields 含 InternalGroupName
  && groupColumns.Count > 1
```

- `isBulkGroup == true` → 一律 `CheckAccept(groupColumns)`（即使 Excel 只有一欄）
- 否則若 Excel 呈現為群組但 BulkDescription 無此群組 → 隱藏
- 其餘維持原單欄規則（AcceptColumns／識別欄／驗證欄／狀態限制）

`InternalGroupName` 在 `SetBulkColumn` 後對應 BulkDescription 的 `GroupName`（例如 XmlField `DisplayText`：`監護人其它資訊`、`前級畢業資訊`），與 `bfields` 的 key 一致。

### `ImportItem.CheckAccept()`

- 比對使用內部欄位名 `BulkColumn.FullDisplayText` 與 `SheetColumns` key（家長1／家長2 已正規化為父親／母親）。
- **僅列出 Excel 實際缺少的欄位**，不列出已存在者。
- 提示文案改為：

```text
Excel「{群組顯示名}」群組欄位不完整。
若要匯入此資料，Excel 尚需包含：

{缺少欄位...}
```

- 缺少欄位／群組顯示名經 `GetParentAliasDisplayText()` 轉換，家長群組 UI 仍顯示 `家長1`／`家長2`。
- 不完整時：`Enabled = false`、`Checked = false`、項目仍可見、Tooltip 說明缺少欄位。

### `btnImport_Click` catch

先前 `(ex as DSAServerException).WarpedError.Response` 在非 DSA 例外時可能二次 NRE。  
改為先安全轉換 `DSAServerException`，確認 `WarpedError.Response` 後再解析；否則顯示原始 `ex.Message`。

## 16. 新群組偵測邏輯（摘要）

```text
BulkDescription 定義群組
→ Excel 欄位與該定義比對
→ 完整群組：可選
→ 不完整群組：欄位選擇頁立即停用並提示缺少欄位
→ 使用者無法勾選不完整群組
→ 驗證／匯入不會再因缺失群組子欄而晚點失敗
```
