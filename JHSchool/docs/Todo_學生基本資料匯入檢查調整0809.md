
## Goal

Adjust the Student Basic Data Import field selection logic.

The import UI must detect whether an Excel field belongs to a multi-field group defined by BulkDescription.

If the Excel file contains only part of a required group, the field must be disabled in the field-selection screen and the user must be informed which related fields are missing.

Do not wait until the final import step to report:

來源資料中不包含此欄位

After completing the modification, record all changes and verification results in:

學生基本資料匯入調整.md


## Current Problem

The current field-selection logic determines whether an ImportItem is a group using:

ImportItem.IsGroupColumn

However, IsGroupColumn is currently determined by the number of columns that happen to exist in the Excel file:

public void AddSheetColumn(SheetColumn column)
{
    if (column.UsedValid)
        Checked = true;

    _columns.Add(column.Name, column);

    if (_columns.Count > 1)
        _is_group_column = true;
}

This means:

If Excel contains only one subfield of a group, for example:

監護人:電話

then:

_columns.Count == 1
IsGroupColumn == false

Therefore the existing CheckAccept() group completeness check is skipped.


## Actual Runtime Behavior

BulkDescription.GenerateUpdateRequest() does not operate strictly by individual selected fields.

It uses:

acceptColumns.ContainGroup(each.SourceName)

If any selected BulkColumn belongs to the group, the whole ElementGenerator for that group is executed.

Example:

Excel contains:

監護人:電話

but does not contain:

監護人:學歷

The selection screen currently allows the field.

During actual import:

監護人:電話 selected
-> acceptColumns contains GroupName = 監護人
-> ContainGroup("監護人") returns true
-> ElementGenerator for 監護人 executes
-> generator attempts to read all fields required by that group
-> reader.GetValue("監護人:學歷")
-> Excel does not contain this column
-> import fails

The same problem occurs with:

前級:學校名稱

when Excel does not contain:

前級:學校所在地


## Important Finding

BulkColumnCollection.GetColumnList() is not the cause.

Current implementation:

public BulkColumnCollection GetColumnList(string[] columns)
{
    return GetInstersection(columns);
}

It only returns the intersection between selected/validated columns and BulkDescription columns.

Do not change GetColumnList() merely to hide this problem.


## Required Design

Determine group membership from the system BulkDescription definition, not from how many matching columns happen to exist in the Excel file.

Use:

Context.BulkDescription.Columns

grouped by:

BulkColumn.GroupName

as the source of truth.


## Existing Group Information

StudentImportWizard already builds:

Dictionary<string, BulkColumnCollection> bfields

through:

GroupBulkColumn(bfields);

This collection represents the actual BulkDescription group definition.

Example conceptually:

bfields["監護人"]
    監護人:電話
    監護人:學歷
    ...

bfields["前級"]
    前級:學校名稱
    前級:學校所在地
    ...

The actual list must come from BulkDescription dynamically.

Do not hard-code group names or field names.


## Required Modification

Review and modify:

StudentImportWizard.DisplayColumns()

Currently the logic uses:

if (each.IsGroupColumn)

to decide whether CheckAccept() should be called.

Do not use Excel-side column count as the authoritative group definition.

Instead, determine whether the current ImportItem belongs to a multi-field BulkDescription group.


## Recommended Logic

For each ImportItem:

1. Use:

each.InternalGroupName

to look up the corresponding group in:

bfields

2. If the BulkDescription group exists and contains more than one BulkColumn:

treat it as a real system-defined group.

3. Call:

each.CheckAccept(groupColumns)

even when the Excel file currently contains only one column of that group.

4. If required group fields are missing:

- set Enabled = false
- set Checked = false
- keep the item visible
- provide a clear tooltip/message listing missing fields

5. If the BulkDescription group contains only one field:

use the existing single-column logic.


## Example Direction

Use logic similar to:

BulkColumnCollection groupColumns = null;

bool isBulkGroup =
    bfields.TryGetValue(
        each.InternalGroupName,
        out groupColumns)
    && groupColumns != null
    && groupColumns.Count > 1;

if (isBulkGroup)
{
    each.CheckAccept(groupColumns);
}
else
{
    // Preserve the existing non-group field logic.
}

Do not copy this blindly without checking the existing class behavior and naming.

## Important: Only List Missing Fields

CheckAccept() should list only fields that are actually missing from the Excel source.

Do not list every field in the group when some are already present.

Likewise:
