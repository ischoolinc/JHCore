# 匯出學生基本資料 — 家長欄位標題調整紀錄

## 問題描述

匯出學生基本資料時，即使在執行階段已將 `Field.DisplayText` 改為：

- `家長1姓名`（原 `父親姓名`）
- `家長2姓名`（原 `母親姓名`）

匯出的 Excel 欄位標題仍然是：

- `父親姓名`
- `母親姓名`

後續亦確認 `XmlField` 展開後的複合欄位標題同樣未轉換：

- `父親:學歷`、`父親:職業`、`父親:電話`
- `母親:學歷`、`母親:職業`、`母親:電話`

## 修改檔案

| 檔案 | 說明 |
| --- | --- |
| `Legacy/Export/ResponseHandler/Connector/ExportStudentConnector.cs` | 在 `Export()` 內、建立 `ExportTable` 前，對所有欄位標題套用與 UI 相同的前綴轉換；並新增 `ConvertParentDisplayText()` |

其餘檔案（`StudentExportWizard.cs`、`ResponseFormater.cs`、`ExportTable.cs`、`ExportOutput.cs`、`FieldUtil.cs`、`JH_S_ExportDescription.xml`）皆未修改。

## 修改的類別與方法

- 類別：`JHSchool.Legacy.Export.ResponseHandler.Connector.ExportStudentConnector`
- 方法：
  - `ExportTable Export()` — 在 `FieldUtil.Match` 之後套用標題轉換
  - `ConvertParentDisplayText(string displayText)` — 新增，邏輯與 UI 端相同

## 除錯 / 追查步驟

依 Todo 要求，追查匯出流程各階段的 `DisplayText` 走向：

### 1. UI 端（`StudentExportWizard.ExportWizard_Load`）

- 以 `BaseFieldFormater.Format()` 從 XML 讀出欄位清單。
- 針對每個欄位呼叫 `ConvertParentDisplayText()`，將開頭 `父親` → `家長1`、`母親` → `家長2`，並寫回 `field.DisplayText`。
- `field.FieldName` 維持不變（`FatherName` / `MotherName` / `FatherOtherInfo` / `MotherOtherInfo`）。
- 這些 `Field` 物件存入 `ListViewItem.Tag`。
- 注意：UI 對 `XmlField` 只顯示一個選項（如 `家長1其它資訊`），不會展開成「學歷 / 職業 / 電話」三個 ListView 項目。

### 2. `SetSelectedFields()`

```csharp
public void SetSelectedFields(FieldCollection fields)
{
    _selectFields = fields;
}
```

- 只是把整個集合的參考存起來，**不會**修改、複製或丟棄 `DisplayText`。
- 結論：`SetSelectedFields()` 不是問題點。

### 3. `Export()`（關鍵）

`Export()` 內部原本完全忽略呼叫端傳入欄位的 `DisplayText`，做法如下：

1. 重新載入匯出規則 XML：`StudentBulkProcess.GetExportDescription()`。
2. 以 `ResponseFormater.Format(descElement)` 重新產生 `ExportFieldCollection`。
   - 單一欄位：`DisplayText` 直接來自 XML（如 `父親姓名`）。
   - `XmlField` 複合欄位：由 `Element DisplayText="父親"` + 子欄位組成（如 `父親:學歷`）。
3. `FieldUtil.Match(exportFields, _selectFields)` 只用名稱比對（`sField.FieldName == field.RequestName`）來決定要保留哪些欄位，保留的是**來自 XML 的 `ExportField` 物件**，呼叫端的執行階段 `DisplayText` 被丟棄。
4. `table.AddColumn(field)` 以這些 `ExportField` 建立欄位。

### 4. 為何複合欄位不能直接套用選取欄位的 `DisplayText`

- 選取欄位：`FieldName=FatherOtherInfo`，`DisplayText=家長1其它資訊`（只有一個）。
- 展開後葉欄位：`FieldName=FatherEducationDegree / FatherJob / Phone`，`RequestName=FatherOtherInfo`，`DisplayText=父親:學歷 / 父親:職業 / 父親:電話`（三個）。
- 若把選取欄位的 `DisplayText` 直接覆寫到三個葉欄位，三欄標題會全部變成 `家長1其它資訊`，遺失區別。

### 5. `ExportOutput`

- 直接使用 `ExportTable.Columns` 內每個 `ExportField.DisplayText` 當作 Excel 標題，沒有重建標題。
- 因此標題值在 `Export()` 階段就已決定。

## 確認的根本原因

屬於 Todo 的 **Case 2 + Case 4**：

> `Export()` 重新載入原始匯出規則 XML 並重新建立 `ExportField`，欄位標題（`DisplayText`）一律取自 XML；`FieldUtil.Match` 只用欄位名稱比對，保留 XML 版本的 `ExportField`，因此呼叫端在執行階段設定的 `DisplayText` 被完全忽略。

對複合欄位另有一層原因：葉節點標題是 `ResponseFormater` 從 XML 的 `Element DisplayText="父親"` 重新組合出來的，與選取欄位的單一 `DisplayText` 不是一對一關係。

## 選用的修正方式與原因

採用 Todo 的 **Preferred Fix 1：在 Connector 內於建立 ExportTable 前修正標題**，並延伸涵蓋複合欄位。

在 `Export()` 內、`FieldUtil.Match` 之後，對**所有**匯出欄位標題套用與 UI 相同的前綴轉換：

```csharp
foreach (ExportField field in exportFields)
{
    field.DisplayText = ConvertParentDisplayText(field.DisplayText);
}

private string ConvertParentDisplayText(string displayText)
{
    if (string.IsNullOrEmpty(displayText))
        return displayText;

    if (displayText.StartsWith("父親"))
        return "家長1" + displayText.Substring("父親".Length);

    if (displayText.StartsWith("母親"))
        return "家長2" + displayText.Substring("母親".Length);

    return displayText;
}
```

轉換結果：

| XML / Export 原標題 | 修正後標題 |
| --- | --- |
| `父親姓名` | `家長1姓名` |
| `母親姓名` | `家長2姓名` |
| `父親:學歷` | `家長1:學歷` |
| `父親:職業` | `家長1:職業` |
| `父親:電話` | `家長1:電話` |
| `母親:學歷` | `家長2:學歷` |
| `母親:職業` | `家長2:職業` |
| `母親:電話` | `家長2:電話` |

### 為何改用前綴轉換（而非直接覆寫選取欄位 DisplayText）

- 單一欄位與複合葉欄位都能正確處理。
- 複合葉欄位各自保留「學歷 / 職業 / 電話」後綴，不會撞名。
- 與 UI 端 `StudentExportWizard.ConvertParentDisplayText()` 行為一致。
- 不修改 XML、不修改內部欄位識別、不影響非父親／母親開頭的欄位。

## 各項確認

- **內部欄位識別維持不變**：只覆寫 `ExportField.DisplayText`，`FieldName`、`RequestName`、`XPath` 完全未動（仍為 `FatherName` / `MotherName` / `FatherOtherInfo` 等）。
- **匯出資料值維持不變**：只影響標題列（第 0 列），資料列的取值與轉換邏輯完全未改。
- **XML 資源維持不變**：`JH_S_ExportDescription.xml` 未做任何修改。
- **其他欄位維持不變**：標題不以 `父親`／`母親` 開頭的欄位不會被轉換。

## 建置結果

- 指令：MSBuild 建置 `JHSchool.sln`（Debug）。
- 結果：**建置成功**（僅有專案原有的警告，無錯誤），產出 `bin\Debug\JHSchool.dll`。

## 測試結果

- 程式建置通過，修正點位於資料流最早可靠處（Connector），確保 `.xlsx` 與 `.xls` 兩種格式的標題皆來自同一個 `ExportField.DisplayText`。
- 預期結果：
  - UI：`家長1姓名`、`家長1其它資訊`、`家長2姓名`、`家長2其它資訊`。
  - Excel 單一欄位：`家長1姓名`、`家長2姓名`。
  - Excel 複合欄位：`家長1:學歷`、`家長1:職業`、`家長1:電話`、`家長2:學歷`、`家長2:職業`、`家長2:電話`。
  - 資料值與內部欄位識別不變。
