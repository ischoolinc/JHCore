# [協同中學] 學生狀態變更後，狀態標籤與學生清單未即時更新 — 修正與測試流程

- Basecamp 待辦：[系統功能修改/新增 事由[協同中學]批次選取學生變更狀態，部分學生狀態都沒有正常變更到。](https://app.basecamp.com/4399967/buckets/15765350/todos/9999684572)（ID `9999684572`）
- 來源：
  1. 測試人員 2026/10/14 回報的額外問題：「如果在學生的資料項目直接變更狀態，那狀態列不會即時呈現，需重新整理頁面才可查看」
  2. 2026/10/14 會議提出：狀態變更後，學生清單不會跟著一起更新
- 與 [updateSpec_批次變更學生狀態快取修正_20261008.md](updateSpec_批次變更學生狀態快取修正_20261008.md) 的修正無關，可分開測試
- 測試環境：ischool〈冠縈展示國中 115 1〉／`demo.j.beibei.lai`／帳號 admin／從 Visual Studio 啟動修改後的 JHSchool
- 版本：沿用 1.0.4.43

## 問題原因

學生狀態有兩個變更途徑，兩者通知其他畫面的方式不同：

| | 學生資料上方的狀態標籤 | 學生清單右鍵「變更學生狀態」 |
|---|---|---|
| 程式位置 | 類別模組（`Tagging.BaseModel.StudentBar`），不在 JHCore | JHCore `ChangeStatusBatch.cs` |
| 寫入方式 | `K12.Data.Student.Update()` | `Feature.EditStudent.ChangeStudentStatus()` 直接呼叫 DSA |
| 引發 K12.Data 的 `AfterUpdate` | 會 | 不會 |
| 狀態標籤是否更新 | 會（類別模組有訂閱 `AfterUpdate`） | **不會 → 問題 1** |
| 學生清單是否更新 | **不會 → 問題 2** | 會（完成後呼叫 `Student.Instance.SyncAllBackground()`） |

1. **狀態標籤沒有即時更新**：批次變更不會引發 `AfterUpdate`，JHCore 也沒有通知類別模組，所以不切換學生時，上方的狀態標籤會一直顯示舊狀態（已實測確認）。
   - 測試人員截圖的情況：學生 060301 已用批次改為「休學」，標籤仍顯示「一般」。接著在標籤選「休學」時，類別模組讀到伺服器上已經是「休學」，判斷狀態相同而不做任何事，所以看起來像「在資料項目變更狀態不會即時呈現」。
2. **學生清單沒有跟著更新**：從狀態標籤變更時只會引發 K12.Data 的 `AfterUpdate`，JHCore 的學生快取（`Student.Instance`）沒有訂閱這個事件，清單與年級樹仍依舊狀態顯示，要手動「重新整理」才會正確。

修正問題 2 後，測試時另外發現兩個問題：

3. **學生離開目前清單時，狀態標籤沒有更新（兩個模組競跑）**：從狀態標籤變更後，類別模組與 JHCore 同時收到 `AfterUpdate`。JHCore 只同步一位學生，很快就刷新完清單，學生不符合篩選被移除、選取被清掉，右側學生資料頁面隱藏；類別模組讀取新狀態時判斷標籤已不在畫面上就不更新（推測為 `StudentBar` 的 `if (!StatusVisible) return;`），標籤停在舊狀態，之後點回同一位學生也不會重新讀取。
   - 排查結果：下中斷點時正常、拿掉就失敗；在清單刷新後補呼叫 `"學生.Tag.Reload"` 有執行到（輸出視窗確認），但同樣撞上「頁面已隱藏」而無效，已移除。
   - 批次變更原本正常，只是因為 `SyncAllBackground` 重新載入全部學生較慢，類別模組通常先做完，同樣是靠時序。
   - 類別模組完成更新時不會發出通知，JHCore 無法用「先後順序」解決。改為**不讓結果取決於誰先做完**：狀態改變的當下，不把右側正在顯示的學生移出清單，頁面不隱藏，類別模組就能照常更新（在待處理檢視中操作從未失敗）。
   - 已用追蹤點確認：從狀態標籤變更與批次變更後的清單刷新過程中，都不會引發選取變更（不會暫時清空選取），所以選取一改變就可以解除保留。
4. **清單刷新後年級樹全部收合、選取的班級消失**：`GradeYear_Class_View.Layout()` 每次都清掉重建，只展開根節點；重建後找回選取結點時比對的是含人數的文字（`國三4(11)` ≠ `國三4(10)`），人數一變就找不到，右側清單被清空。批次變更完成後的 `SyncAllBackground` 也會走同一段，修改前就有這個現象。

核對程式時另外發現一個原本就存在的問題，一併修正：

5. **上方「刪除」按鈕擋不下重複的身分證號**：刪除前會檢查「刪除」狀態中是否已有相同學號或身分證號的學生（註解與錯誤訊息都寫明兩者都要檢查），但判斷式誤寫成 `tmpSnumList.Contains(studRec.IDNumber)`，拿身分證號去學號清單比對，收集好的身分證號清單 `tmpStudIDNumberList` 沒有用到，所以只有學號重複會被擋下。
   - 從 repo 最早的版本（2013/12/26）就是這樣寫，不是近期修改造成的。
   - 同類的檢查（右鍵批次變更 `ChangeStatusBatch.cs`、類別模組的狀態標籤）都有正確檢查身分證號，只有這段寫錯。

## 修改內容

| 檔案 | 修改 |
|---|---|
| `JHSchool/ChangeStatusBatch.cs` `_BKW_RunWorkerCompleted` | （問題 1）變更成功後呼叫 `FISCA.Features.Invoke("學生.Tag.Reload")`，通知類別模組重新讀取目前學生的狀態。呼叫前用 `FISCA.Features.FeatureMap.ContainsKey` 確認已註冊，沒有載入類別模組時略過。另在 `SyncAllBackground()` 前呼叫 `KeepDisplayedInList`（見問題 3） |
| `JHSchool/Student.cs` 學生面板初始化 | （問題 2）訂閱 `K12.Data.Student.AfterUpdate`，對被變更的學生呼叫 `SyncDataBackground`，同步完成後清單與年級樹依狀態篩選重新顯示。事件若在背景執行緒引發，先用 `MotherForm.Form.BeginInvoke` 回到 UI 執行緒 |
| `JHSchool/Student.cs` | （問題 3）**暫時保留正在顯示的學生**：<br>・`KeepDisplayedInList`：狀態變更（`AfterUpdate` 同步、批次變更）時，若右側學生資料頁面正在顯示的學生（`DetailContents` 的 `PrimaryKey`）在變更名單中且仍被選取，記入保留清單 `_KeepKeys`。批次變更時其他一起選取的學生不保留<br>・`FillFilter`：依篩選算出清單後，再加入保留清單中的學生<br>・解除：選取變更（`SelectedListChanged`：改選其他學生、點選年級樹結點時選取變成空的）時解除不再選取的學生並重新篩選；切換篩選條件、年級樹右鍵「重新整理」時全部解除<br>・`_FillingFilter`：`SetFilteredSource` 期間忽略選取變更，避免重入 |
| `JHSchool/StudentExtendControls/GradeYear_Class_View.cs` `Layout()` | （問題 4）重建前記錄已展開的結點，重建後展開回去；記錄與找回選取結點時改用去掉人數的名稱比對（新增 `GetNodeName`），人數改變後仍保留原本選取的班級 |
| `JHSchool/Student.cs` 上方「刪除」按鈕 | （問題 5）身分證號改用身分證號清單比對。比照批次變更，學號、身分證號都去除前後空白，身分證號不分大小寫；學號或身分證號空白時不檢查（維持「空白可刪」） |

- 問題 1 的做法參考 SHCore 教師管理的 `FISCA.Features.Invoke("教師.Tag.Reload")`。
- 問題 2 的做法 SHCore 沒有前例（SHCore 批次變更是廣播「學生/資料變更」），所以要測試副作用（見 T10）。SHCore 從狀態標籤變更後清單不會更新，會出現清單內容不符合篩選條件的情況，所以國中版維持更新清單。
- 問題 3 不修改類別模組。

### 使用上的改變（回覆測試人員時需說明）

- 狀態變更後，右側正在顯示的學生會**暫時留在清單**（即使已不符合篩選），年級樹人數也暫時把他算在內；改選其他學生、點選年級樹結點、切換篩選或重新整理後，才依篩選移除、人數更新。
- 批次變更時，只有右側正在顯示的那一位暫時保留，其他一起選取的學生在批次完成後馬上依篩選移除。
- 上方功能按鈕「刪除」是把狀態改成「刪除」（不是永久刪除），適用同樣的規則：按下後學生不會像修改前一樣馬上消失，標籤會顯示「刪除」。
- 年級樹在資料更新後維持原本的展開狀態與選取的班級。
- 上方「刪除」按鈕：若「刪除」狀態中已有相同身分證號的學生，會跳出「刪除狀態有重複學號或身分證號，請先修改後再刪除！」而不刪除（修改前只檢查學號）。

## 測試前準備

1. 從 Visual Studio 啟動，登入測試環境。
2. 選定國三4 的 3 位測試學生，記錄目前的狀態與英文姓名，並記錄年級樹上 3 年級、國三4 的人數。
3. 把這 3 位學生「加入至待處理」。學生改成非在校狀態後會從班級清單消失，從待處理才能繼續選到。
4. 記錄學生清單篩選（漏斗）目前勾選的項目，測試時除特別註明外，**篩選只勾「一般」**。
5. 確認測試學生的學號、身分證號沒有和「刪除」狀態的學生重複（T6 刪除學生時會檢查）。

### 名詞

- **班級檢視**：左側年級樹選取國三4 後顯示的清單，受篩選條件影響。
- **待處理檢視**：左下「待處理學生」的清單，不受篩選條件影響。
- **保留**：狀態變更後，右側正在顯示的學生暫時留在班級清單中。
- **離開**：改選其他學生、點選年級樹結點、切換篩選、右鍵「重新整理」。

### 判斷結果的依據

- **狀態標籤**：右側學生資料上方的狀態文字與底色（一般：白、畢業或離校：綠、休學／輟學：黃、刪除：紅）。
- **學生清單與年級樹**：清單中的學生，以及年級樹各結點的人數、展開狀態、選取的結點。
- **系統歷程**：左上角選單 >> 系統歷程 >> 查詢系統歷程。
  - 批次變更：功能「變更學生狀態」，描述「學生：(學號)姓名 狀態由「A」變更為「B」」
  - 從狀態標籤變更：功能「學生狀態」，描述「學生「姓名」狀態已由「A」變更為「B」」
  - 上方「刪除」按鈕：功能「學籍學生」，描述「刪除學生，姓名:X,學號:Y」

## 測試案例

| 分類 | 案例 |
|---|---|
| 問題 1：批次變更後狀態標籤即時更新 | T1、T2 |
| 問題 2、3：清單同步與保留 | T3、T4、T5、T6 |
| 問題 3：解除保留的時機 | T7 |
| 問題 4：年級樹展開與選取 | T8 |
| 回歸與副作用 | T9、T10、T11 |
| 問題 5：刪除按鈕的重複檢查 | T12 |

### T1. 批次變更單一學生，狀態標籤即時更新（待處理檢視）

1. 在待處理選取一位學生，確認右側狀態標籤為「一般」。
2. 右鍵 →「變更學生狀態」→「休學」→ Yes。**不要切換學生、不要重新整理。**
3. 同一位學生再用右鍵改回「一般」。

**預期結果**

- [ ] 第 2 步：狀態標籤馬上變成「休學」（黃底），點開標籤的選單，打勾的是「休學」。修正前會一直顯示「一般」，要切換學生才會變。
- [ ] 第 3 步：標籤馬上變回「一般」。
- [ ] 狀態列顯示「變更學生狀態成功，共 1 位學生」；系統歷程各有一筆「變更學生狀態」的紀錄。

### T2. 批次變更多位學生，狀態標籤顯示目前學生的狀態（待處理檢視）

1. 在待處理選取 3 位學生（右側顯示其中一位），右鍵變更為「休學」。
2. 逐一點選這 3 位學生。
3. 3 位一起改回「一般」。

**預期結果**

- [ ] 變更完成時，右側正在顯示的學生，標籤馬上變成「休學」。
- [ ] 逐一點選時，每一位的標籤都是「休學」。
- [ ] 3 位一直留在待處理清單中；狀態列顯示「共 3 位學生」。

### T3. 從狀態標籤變更，清單同步並保留正在顯示的學生（班級檢視）

1. 班級檢視選取國三4，點選一位「一般」學生。
2. 點右側狀態標籤 →「休學」→ 確認視窗按「Yes」。
3. 點選國三4 其他學生。
4. 到待處理點選這位學生。
5. 用狀態標籤改回「一般」，再點選待處理的其他學生，回到班級檢視國三4。

**預期結果**

- [ ] 第 2 步：狀態標籤即時變成「休學」，學生留在國三4 清單，右側頁面不消失。
- [ ] 第 3 步：這位學生才從清單消失，年級樹人數減 1（例：`國三4(11)` → `國三4(10)`），國三4 維持選取，清單顯示該班其餘學生。修正前要手動「重新整理」清單才會更新。
- [ ] 第 4 步：狀態標籤顯示「休學」。保留機制加入前會顯示舊的「一般」（兩個模組競跑）。
- [ ] 第 5 步：學生依篩選重新出現在國三4，年級樹人數恢復。
- [ ] 系統歷程有「學生狀態」的紀錄。

### T4. 批次變更單一學生（班級檢視）

1. 班級檢視選取國三4，點選一位學生，右鍵改成「休學」。
2. 點選國三4 其他學生。
3. 到待處理點選這位學生，確認標籤後改回「一般」。

**預期結果**

- [ ] 第 1 步：學生留在清單、右側頁面不消失，標籤馬上變成「休學」。
- [ ] 第 2 步：這位學生才從清單消失，國三4 人數減 1。
- [ ] 第 3 步：標籤是「休學」。

### T5. 批次變更多位學生，只保留正在顯示的學生（班級檢視）

1. 班級檢視選取國三4，選取 3 位學生（記下右側顯示的是哪一位），右鍵改成「休學」。
2. 點選國三4 其他學生。
3. 到待處理把 3 位改回「一般」。

**預期結果**

- [ ] 第 1 步：只有右側正在顯示的學生留在清單，標籤即時變成「休學」；另外 2 位在批次完成後馬上從清單消失，國三4 人數減 2（暫時把保留的學生算在內）。
- [ ] 第 2 步：保留的學生從清單消失，國三4 人數再減 1，為正確值。
- [ ] 到待處理逐一點選 3 位，標籤都是「休學」。

### T6. 上方功能按鈕「刪除」學生（班級檢視）

1. 班級檢視選取國三4，只點選一位學生，按上方功能按鈕「刪除」→ 確認視窗「確定要刪除「姓名」？」按「Yes」。
2. 點選國三4 其他學生。
3. 到待處理點選這位學生，用狀態標籤改回「一般」。

**預期結果**

- [ ] 第 1 步：沒有錯誤訊息；狀態標籤即時變成「刪除」（紅底），學生暫時留在清單。修改前按下後馬上消失。
- [ ] 第 2 步：學生從清單消失，國三4 人數減 1。
- [ ] 第 3 步：標籤顯示「刪除」，改回「一般」後依篩選回到國三4。
- [ ] 系統歷程有一筆「刪除學生」的紀錄。

> 備註：若跳出「刪除狀態有重複學號或身分證號，請先修改後再刪除！」，代表「刪除」狀態中已有相同學號的學生（例：之前測試沒有還原），請換一位學生或先處理重複資料。

### T7. 解除保留的時機

每一項都先用狀態標籤把國三4 一位學生改成「休學」（學生保留在清單），再用指定的操作離開，測完把學生改回「一般」再測下一項：

1. 點選國三4 其他學生。
2. 點選年級樹其他結點（例：國三4 → 301）。
3. 切換篩選條件（例：勾選再取消「休學」）。
4. 在年級樹按右鍵「重新整理」。
5. 被保留的學生是該班唯一一位學生時，點選年級樹其他班級結點。需要有只剩一位符合篩選學生的班級才能測；找不到時可略過，原理與第 2 步相同（點選結點時選取變成空的，就會解除保留）。

**預期結果**

- [ ] 1～4：被保留的學生依篩選從班級清單與年級樹移除，人數正確。
- [ ] 5：該生與只剩他一人的班級結點一起從年級樹消失。
- [ ] 清單不會出現重複的學生，也沒有明顯閃爍或錯誤訊息。

> 備註：
> - 在清單空白處點一下不會取消選取，所以不會解除保留。
