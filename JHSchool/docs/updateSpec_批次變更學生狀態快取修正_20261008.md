# [協同中學] 批次變更學生狀態 — 快取修正測試流程

- Basecamp 待辦：[系統功能修改/新增 事由[協同中學]批次選取學生變更狀態，部分學生狀態都沒有正常變更到。](https://app.basecamp.com/4399967/buckets/15765350/todos/9999684572)（ID `9999684572`）
- 測試環境：ischool〈冠縈展示國中 115 1〉／`demo.j.beibei.lai`／帳號 admin／從 Visual Studio 啟動修改後的 JHSchool

## 問題原因

`K12.Data.Student.SelectByIDs`、`SelectAll` 都會先讀 K12.Data 的用戶端快取（`EntityCache`）。
`Feature.EditStudent.ChangeStudentStatus` 直接呼叫 DSA `SmartSchool.Student.Update` 變更狀態，不會清除這份快取。

所以同一個執行階段裡，快取可能還是學生的舊狀態：

1. [ChangeStatusBatch.cs](../ChangeStatusBatch.cs) 判斷「狀態已經等於目標狀態」時用到舊狀態，學生被**略過**。被略過的學生不會送出、不會寫歷程，畫面也沒有錯誤提示。
2. 哪些學生的快取是舊的，取決於 DBMonitor 什麼時候清除快取，所以失敗的學生每次都不一樣。
3. 重新啟動程式後快取是空的，所以在 Visual Studio 重新執行時無法重現。

## 修改內容

| 檔案 | 修改 |
|---|---|
| `JHSchool/ChangeStatusBatch.cs` `_BKW_DoWork` 開頭 | 在 `SelectAll` 之前呼叫 `K12.Data.Student.RemoveByIDs(選取的學生)`，讓這些學生在重複檢查和變更判斷時都讀到伺服器上的最新狀態 |
| `JHSchool/Feature/EditStudent.cs` `ChangeStudentStatus` | 呼叫 DSA 後在 `finally` 中執行 `K12.Data.Student.RemoveByIDs(ids)`，讓之後讀取這些學生的模組拿到新狀態 |
| `JHSchool/ChangeStatusBatch.cs` 狀態列 | 開始變更時先顯示「變更學生狀態...」，蓋掉上一次的訊息；完成後依結果顯示下表的訊息 |
| `JHSchool/Properties/AssemblyInfo.cs` | 版本 1.0.4.42 → 1.0.4.43 |

`SelectAll` 的其他學生維持使用快取，不影響大型學校的效能。

### 狀態列訊息

| 結果 | 狀態列 | 其他提示 |
|---|---|---|
| 有學生變更成功 | 變更學生狀態成功，共 N 位學生 | — |
| 所有學生都已是目標狀態 | 所選學生狀態已是「X」，未變更任何學生 | — |
| 重複檢查擋下 | 變更學生狀態未執行 | 跳出重複學號／身分證號訊息 |
| 發生例外 | 變更學生狀態發生錯誤 | 跳出錯誤訊息 |

選「輟學」時，實際寫入的狀態是「延修」，所以訊息中的 X 會顯示「延修」。

## 測試前準備

1. 從 Visual Studio 啟動，登入測試環境。
2. 記錄國三4 目前每位學生的狀態（上一輪測試結束時，陳子義、黃子瑀、徐子瑄、羅子呈、翟皓柏為「畢業或離校」，其他 6 人為「一般」；在 VS 測試過後可能已改變）。
3. 如果要把學生還原成同一個起始狀態，先把國三4 全部改成「一般」。
4. **先把要測試的學生加入「待處理」，之後都在待處理檢視中選取和變更。** 學生改成「畢業或離校」等非在校狀態後會從在校學生清單消失，在待處理裡才能繼續選到同一批學生。
5. 測試 T3 時需要開兩個 ischool：Visual Studio 啟動的是主要測試環境，另一個用來模擬第二位使用者。

### 判斷結果的依據

- **狀態列**：每次變更都會先顯示「變更學生狀態...」，完成後顯示「變更學生狀態成功，共 N 位學生」。N 應該等於實際變更的人數。
- **系統歷程**：功能「變更學生狀態」，每位實際變更的學生一筆。
- **清單人數**：改成「畢業或離校」後，學生會從在校清單消失，人數會減少。
- **逐一確認**：點開學生確認狀態（右側資料載入會延遲 3～5 秒，請等載入完成再看）。

## 測試案例

### T1. 連續來回變更（主要重現案例）

修改前：第二次變更時整批失敗。

1. 全選國三4（11 人），右鍵 →「變更學生狀態」→「畢業或離校」→ Yes。
2. **完全不要動畫面**，馬上在同一批學生上右鍵 →「變更學生狀態」→「一般」→ Yes。
   - 如果學生在第 1 步已經從清單消失，請改用「待處理」或「畢業或離校」的檢視選取同一批學生。
3. 再重複一次第 1 步和第 2 步。

**預期結果**

- [ ] 每一次變更都是 11 人全部成功，狀態列顯示「變更學生狀態成功，共 11 位學生」。
- [ ] 每一次變更都有 11 筆系統歷程。
- [ ] 沒有跳出「學號／身分證號…有相同學號無法變更」的訊息（確認不會和自己的舊快取比對到）。

### T2. 部分學生已經是目標狀態

確認「狀態相同才略過」的判斷仍然正確。

1. 讓國三4 部分學生為「畢業或離校」、部分為「一般」（例如先只選 5 位改成「畢業或離校」）。
2. 不要動畫面，選取國三4 全部 11 人，變更為「畢業或離校」。

**預期結果**

- [ ] 原本是「一般」的 6 人變更成功，有 6 筆系統歷程，狀態列顯示「共 6 位學生」。
- [ ] 原本已是「畢業或離校」的 5 人沒有新的歷程（正確略過）。
- [ ] 最後 11 人都是「畢業或離校」。
- [ ] 再對同一批 11 人變更一次「畢業或離校」：狀態列顯示「所選學生狀態已是「畢業或離校」，未變更任何學生」，沒有新的歷程。

### T3. 其他人或其他途徑改了狀態

確認讀到的是伺服器上的最新狀態，而不是這台電腦的快取。

1. 在 VS 啟動的程式中，先點開國三4 幾位學生，讓快取載入資料。
2. 用**另一台電腦或另一個 ischool 視窗**，把國三4 其中 2～3 位改成「畢業或離校」。
3. 回到 VS 啟動的程式，**馬上**全選國三4，變更為「畢業或離校」。

**預期結果**

- [ ] 剩下的學生全部變更成功，最後 11 人都是「畢業或離校」。
- [ ] 系統歷程只有本次實際變更的學生，在另一台電腦改過的學生不會重複寫入。

### T4. 用中斷點確認快取已被清除（選做）

1. 在 `ChangeStatusBatch.cs` 的 `foreach (K12.Data.StudentRecord stud in allStudentList)` 那一行下中斷點。
2. 依 T1 的步驟，在第 2 步（改回「一般」）停在中斷點時，在即時運算視窗輸入：
   ```csharp
   allStudentList.Find(s => s.Name == "陳子義").Status
   ```

**預期結果**

- [ ] 顯示「畢業或離校」（伺服器上的最新狀態）。修改前這裡會顯示舊的「一般」。

### T5. 超過 100 人的批次（分批送出）

`ChangeStatusBatch` 每 100 人送出一批，確認每一批送出後都有清除快取。

1. 選取 100 人以上的學生（例如整個 3 年級），變更為「畢業或離校」。
2. 不要動畫面，同一批學生再改回「一般」。

**預期結果**

- [ ] 兩次都全部成功，系統歷程的筆數等於選取人數。
- [ ] 測試後確認人數已還原（3 年級人數和測試前相同）。

> 這個案例影響的學生較多，請先確認測試環境可以這樣操作，結束後一定要還原。

### T6. 其他狀態（回歸測試）

在國三4 中選幾位學生，依序變更為「休學」→「一般」→「輟學」→「一般」，每一步都不要動畫面。

**預期結果**

- [ ] 每一步都成功，系統歷程筆數正確。
- [ ] 「輟學」實際寫入的狀態是「延修」（原本的程式行為，不在這次修改範圍內）。

### T7. 真正的重複資料仍然會被擋下（選做）

確認重複檢查沒有被這次修改影響。

1. 找一位「畢業或離校」學生的學號，把國三4 某位「一般」學生的學號改成相同的值。
2. 把這位國三4 學生變更為「畢業或離校」。

**預期結果**

- [ ] 跳出「學號:xxx在畢業或離校有相同學號無法變更」，狀態列顯示「變更學生狀態未執行」，整批都沒有變更。
- [ ] 測試後把學號改回原本的值。

## 測試後還原

- [ ] 國三4：還原成測試前記錄的狀態。
- [ ] 如果有執行 T5：3 年級人數和測試前相同。
- [ ] 如果有執行 T7：學號已改回原本的值。
- [ ] 待處理清單：移除測試用的學生。

## 尚未處理（不在這次修改範圍）

- `_BKW_DoWork` 在背景執行緒讀取 `NLDPanels.Student.SelectedSource` 共 4 次。如果執行中選取範圍改變，讀到的學生可能不一致。
- `SelectAll` 中「非選取學生」仍使用快取。只有當這些學生剛被別人改過狀態、學號或身分證號又剛好重複時，重複檢查才可能誤擋或漏擋，機率很低。
- `ChangeStudentStatus` 沒有檢查 DSA 回傳的 `DSResponse`。
