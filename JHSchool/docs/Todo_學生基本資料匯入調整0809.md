
## Goal

Adjust the Student Basic Data Import function so that Excel/UI uses the new parent field names:

* 家長1
* 家長2

while the internal import structure, XML structure, and database storage continue to use the existing:

* 父親
* 母親

After completing the modification, record all changes and verification results in:

學生基本資料匯入調整.md

## Important Requirements

1. Do not change the existing database XML structure.
2. Do not rename the internal 父親 / 母親 fields.
3. Do not change unrelated import logic.
4. Do not change the existing Insert / Update architecture.
5. Do not change BulkDescription, BulkColumn, or StudentBulkProcess unless absolutely necessary.
6. Prefer handling the new/legacy Excel field conflict in SheetReader.NormalizeParentImportFieldNames().
7. Preserve existing behavior for all non-parent fields.

## Current Design

Excel/UI field names:

家長1xxx
家長2xxx

Internal import field names:

父親xxx
母親xxx

Example:

家長1姓名 -> 父親姓名
家長1電話 -> 父親電話
家長1:學歷 -> 父親:學歷

家長2姓名 -> 母親姓名
家長2電話 -> 母親電話
家長2:學歷 -> 母親:學歷

SheetColumn.SourceName must continue to represent the actual Excel column name.

SheetColumn.Name must continue to represent the internal import field name.

## Problem to Fix

The current NormalizeParentImportFieldNames() converts:

家長1姓名 -> 父親姓名

and leaves:

父親姓名 -> 父親姓名

Therefore, when the Excel file contains both:

家長1姓名
父親姓名

both columns become the internal field:

父親姓名

and the current code throws:

重覆的欄位名稱：父親姓名

The same problem exists for:

家長2xxx + 母親xxx

## Required Parent Field Priority Rule

New Excel field names must always have priority over legacy field names.

### Rule 1

If Excel contains only:

家長1姓名

use it and normalize it internally to:

父親姓名

### Rule 2

If Excel contains only:

父親姓名

keep the column available internally so the existing UI validation can detect it.

However, the import selection UI must continue to reject it because the Excel field name is not 家長1姓名.

### Rule 3

If Excel contains both:

家長1姓名
父親姓名

then:

* Use 家長1姓名.
* Normalize 家長1姓名 to internal 父親姓名.
* Ignore the legacy Excel 父親姓名 column.
* Do not throw a duplicate-column exception.

### Rule 4

If Excel contains both:

家長2姓名
母親姓名

then:

* Use 家長2姓名.
* Normalize 家長2姓名 to internal 母親姓名.
* Ignore the legacy Excel 母親姓名 column.
* Do not throw a duplicate-column exception.

## Matching Must Be Per Field

Do not remove all 父親 fields just because any 家長1 field exists.

The priority comparison must use the exact corresponding internal field name.

Example:

家長1姓名 + 父親姓名
=> 家長1姓名 wins.

家長1電話 + 父親電話
=> 家長1電話 wins.

But:

家長1姓名 + 父親電話

are different fields.

Both must remain independently processable according to their own rules.

## Recommended Implementation

Modify:

SheetReader.NormalizeParentImportFieldNames()

Use a two-pass approach.

### Pass 1

Scan the original Excel columns.

For each Excel column beginning with:

家長1
家長2

calculate its corresponding internal field name and store it in a preferred-parent-field collection.

Example:

家長1姓名 -> 父親姓名
家長1電話 -> 父親電話
家長2姓名 -> 母親姓名

### Pass 2

Process all Excel columns.

For a 家長1 / 家長2 column:

* Normalize it to 父親 / 母親.
* Keep the original SourceName.
* Add it to the normalized collection.

For a legacy 父親 / 母親 column:

* Determine its internal field name.
* If the same internal field is already represented by a 家長1 / 家長2 Excel column, skip the legacy column.
* Otherwise keep the legacy column.

For all other columns:

* Keep the existing behavior unchanged.

## Important SheetColumn Behavior

Do not change this design:

SourceName
= actual Excel header

Name
= internal import field name

Example after normalization:

Excel:

家長1姓名

must become logically:

SourceName = 家長1姓名
Name = 父親姓名

The physical Excel column index must still point to the 家長1姓名 column.

Therefore:

reader.GetValue("父親姓名")

must return the value physically stored in Excel column:

家長1姓名

## UI Behavior Must Remain

The import selection screen must continue to display:

家長1
家長2

instead of:

父親
母親

The existing validation rule must remain:

* Excel 家長1xxx -> selectable.
* Excel 家長2xxx -> selectable.
* Excel legacy 父親xxx only -> not selectable.
* Excel legacy 母親xxx only -> not selectable.

Do not weaken TryValidateParentSourceNames() so that old 父親 / 母親 Excel fields become selectable.

## XML / Database Requirement

Do not change the existing XML/database parent structure.

The final data flow must remain:

Excel 家長1xxx
-> SheetColumn.SourceName = 家長1xxx
-> SheetColumn.Name = 父親xxx
-> BulkColumn 父親xxx
-> existing GenerateInsertRequest / GenerateUpdateRequest
-> existing XML 父親 structure
-> database

and:

Excel 家長2xxx
-> SheetColumn.SourceName = 家長2xxx
-> SheetColumn.Name = 母親xxx
-> BulkColumn 母親xxx
-> existing GenerateInsertRequest / GenerateUpdateRequest
-> existing XML 母親 structure
-> database

## Do Not Implement This Incorrectly

Do not:

* Rename XML 父親 to 家長1.
* Rename XML 母親 to 家長2.
* Rename database fields.
* Add duplicate parent data to XML.
* Select whichever column appears first in Excel.
* Select whichever column appears last in Excel.
* Depend on Dictionary enumeration order.
* Remove all 父親 fields when only one 家長1 field exists.
* Remove all 母親 fields when only one 家長2 field exists.
* Hide errors with catch(Exception) or null-coalescing without fixing the mapping problem.
